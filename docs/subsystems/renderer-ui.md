# 渲染层与界面

状态：Current。主要文件在 `desktop/src/renderer/`。

## 组成

| 文件 | 界面 |
| --- | --- |
| `index.html` + `app.mjs` + `styles.css` | 主窗口：Bot 网格、聊天页、收件页、设置页 |
| `composer.html` + `composer.mjs` + `composer.css` | 悬浮输入框；同一 HTML 以 `?part=avatar` / `?part=picker` 复用为头像窗和格子宫格 |
| `native-avatar.mjs` | 给 Swift WKWebView 用的离线头像桥 |
| `group-avatar.mjs` | 同名分组、分组头像与 `listedBots` |
| `preload.cjs` | 唯一 IPC 入口，暴露白名单方法给渲染层 |

渲染层**没有** Node、文件系统、token。它只拿主进程给的 state 快照，并通过 `anywhere:call(method, params)` 请求动作。

## 主窗口

- 左侧：搜索、Bot 网格（按置顶/用户分组/未分组分区）、底部导航（Bot / 收件 / 设置）。
- 中间：Bot 详情（头像、名称、描述、成员/群组）、收件列表、设置面板。
- 顶栏：搜索、刷新、分组开关；Windows 额外显示最小化/最大化/关闭。
- 所有用户可见字符串走 `t()`（中英双语），跟随系统语言。

### 设置页分组

| 分组 | 内容 |
| --- | --- |
| 常规 | 账号登录/退出、开机自启动、外观；WhatsApp / 通用来源各自的默认 Bot 和前缀；可选的 WhatsApp 导出文件夹监视（默认关闭）。显示当前路径，「选择文件夹」走系统文件夹选择器，「恢复为下载文件夹」回到默认。换目录后只导入之后新出现的文件 |
| 快捷键 | 唤起输入框的全局快捷键；录制时临时注销 |
| 输入框 | 发送后隐藏或打开 Grok Bot、点击外部收起；单个 Bot 可覆盖 |
| 分享菜单 | 12 槽的启用/顺序/重新同步；复制报错日志；系统共享菜单自动刷新 |
| 工具箱 | 关闭全部接收转发；命令行与 skills；Windows Explorer 菜单 |

> macOS 端暂时隐藏「快捷指令」来源 chip 和「复制快捷指令链接」行；后端深链入口仍保留。

## Bot 详情

- 主区域只保留头像、名称和「开始对话 / 在 Grok Bot 中打开 / 更多」。
- 指令描述不在主区域铺开；「更多 → 查看详情」在模态里用 Markdown 渲染完整描述，并显示 ID、类型和群成员。
- 「查看发送记录」「复制此 Bot」「查看详情」放在 More 菜单中；菜单是固定定位 portal，滚动/缩放/点击外部都会关闭，支持方向键、Home/End、Esc。
- 链接只允许 http(s)/mailto，原始 HTML 会被转义。

## 悬浮输入框

- 368×120 的原生窗口，透明背景；内部是普通 `<textarea>`，不是自绘编辑器。
- 顶部短横条是拖动把手；窗口可移动，位置改变后头像窗和 Tab 宫格跟着卡片走，不再被 `placeComposer` 拉回屏幕底部。
- 工具栏始终有收起按钮；点击外部是否收起仍由设置决定。Esc 只收起输入框，不会隐藏或关闭主窗口。
- 回车发送、Shift+回车换行；输入法组合期间不发送。
- Tab 打开 10×2 宫格；`1–0`、`−`/`+`、方向键、回车、Tab 确认，Esc 取消。
- 支持拖入文件；文件只登记路径，发送时才复制/上传。附件 chip 可以逐个点掉；用户主动关闭输入框时清空本次附件，并清除收件副本、标记 `composerDismissed`，之后启动不再自动弹出该草稿。
- Tab 宫格只更新选中态，不重建头像节点；移动选框不会让所有头像重新加载。确认切换到另一个 Bot 后，焦点回到输入框，可以直接继续打字。
- 悬浮输入框先以透明窗口完成卡片和头像渲染，两者就绪后一次性放到最终位置并以约 160ms 淡入，避免先出现在上方再被头像挤下去。
- 发送时输入框收起为 320px 小条：左侧 Bot 头像，右侧标题、进度条和状态文字，最右是关闭按钮。关闭小条只停止显示，不中止发送；发送完成前小条保持可见。
- 进度来自服务进程的 receipt：上传阶段显示文件/字节进度，发送阶段显示不确定进度；`sent` 显示完成并约 2.5 秒后自动收起，失败/未确认/过期保留小条等用户关闭。
- 小条收起后下一次唤醒必须重新显示卡片：`renderBar()` 会把 `#card.hidden` 设为 `true`，所以回到卡片时显式 `card.hidden=false`，不能只靠 `data-part` CSS。
- 附件总大小或单个附件超过 50 MB 时先显示二次确认；回车继续发送，Esc 取消。上传仍可能失败，失败会留在发送记录。
- 发送成功后：默认隐藏输入框，或在 Grok Bot 中打开对应 Bot；单个 Bot 的设置优先于全局。
- 系统分享先打开输入框并显示“正在载入附件…”，附件在后台导入；用户可以同时输入文字。导入完成后附件自动补到同一个草稿，发送按钮在附件准备好前禁用。
- 点击外部是否收起由设置决定（`composer-prefs.json`）。关闭输入框不会隐藏主窗口；主窗口已经打开时焦点回到主窗口，主窗口没打开时也不会唤醒它。关闭期间会短暂抑制应用的 activate 事件。
- 点击穿透：主进程 `setIgnoreMouseEvents` 由渲染层 `setHit` 控制。

## 主题与外观

- CSS 变量：亮色画布 `#f4f3f0`、暗色 `#0b0b0c`，表面约 86%/84% 不透明，强调色 `#f59312`。
- 圆角、发丝线、阴影只用于层次；不用彩色左边条表示状态。
- 头像：Electron 用 `avatar-adapter.mjs` 包装的 `grok-bot-avatar-engine` 0.1.0（26 个形状，含 `pumpkin`）；列表用 IntersectionObserver 懒启动/停止动画。Bot 详情支持应用内头像编辑，26 个形状 × 11 个颜色全部开放。
- 自定义头像图片按容器尺寸 `object-fit: cover` 填充并裁成圆角；输入框、Tab 宫格和分享选择面板都走同一规则。图片加载失败时回退角色头像，不留下空白图。
- 减少动态效果时显示静帧。
- Bot 详情的选中态用 Bot 自身强调色；文字颜色由 `accentInk` 计算为 `--on-accent`，白色/浅色 Bot 上不再使用白字。

## 状态与事件

- 主进程推送 `anywhere:event`：`state`、`navigate`、`login.url`、`reply`、`share.received`、`picker`、`pick`、`window-state`。
- 渲染层不缓存业务真相；每次 `state` 全量覆盖视图。切换页面只影响选择，不改变服务状态。
- 搜索/分组/主题等 UI 偏好保存在渲染层内存或主进程 JSON；账号、receipt、recipient 在 SQLite。

## 约束

1. 不要给渲染层加 Node 集成或直接读文件；需要新能力就加 preload + 主进程白名单方法。
2. 不要在渲染层写发送重试逻辑；状态机在服务进程。
3. 新增用户可见文字必须同时给中英文；测试会检查关键标签。
4. 不要用原生 `<select>` 做重要选择；用应用内菜单/自定义控件保持一致。
5. 修改 `index.html` 的 CSP 前先确认没有引入远程脚本。
